# Collaborative To-Do List

A terminal-based task management application implemented in **JavaScript with Node.js** and **Java**. Both versions provide the same core user and task operations while demonstrating different language features, including classes, collection operations, JSON persistence, and concurrency.

## Application functionality

- Create users and display the user list.
- Create tasks with a title, category, and assigned user.
- Display all tasks or filter by user or category.
- Track tasks as `Pending` or `Completed`.
- Mark tasks as completed, delete tasks, and reassign tasks.
- Delete a user and their assigned tasks after confirmation.
- Reject duplicate usernames, ignoring capitalization.
- Reject duplicate task titles assigned to the same user, ignoring capitalization, including during reassignment.
- Save successful changes to JSON and reload them on startup.
- Demonstrate two overlapping task creation operations without changing saved application data.

## Requirements

- **JavaScript:** Node.js installed and available through the `node` command. No additional npm packages are required.
- **Java:** JDK 17 or newer, with both `java` and `javac` available. Gson is included in `java/lib/`.
- **Both:** A terminal and permission to write saved data in the application folders.

Check the installed tools:

```bash
node --version
java -version
javac -version
```

## Download the project

```bash
git clone https://github.com/karthikpenta-git/Collaborative-ToDo-List.git
cd Collaborative-ToDo-List
```

Run all commands below from this repository root.

## Run JavaScript

```bash
node javascript/app.js
```

JavaScript runs directly through Node.js; no separate build step is required. Enter a menu option and follow the prompts.

## Compile and run Java

### macOS or Linux

```bash
mkdir -p java/out
javac -encoding UTF-8 -cp "java/lib/*" -d java/out java/*.java
java -cp "java/out:java/lib/*" Main
```

### Windows PowerShell

```powershell
New-Item -ItemType Directory -Force java/out
javac -encoding UTF-8 -cp "java/lib/*" -d java/out java/*.java
java -cp "java/out;java/lib/*" Main
```

Recompile after changing Java source files. The runtime classpath uses a colon on macOS/Linux and a semicolon on Windows.

## Terminal menu

Both implementations use the following options, grouped into create, view, update/delete, and demo/exit sections:

| Option | Operation |
| --- | --- |
| 1 | Create user |
| 2 | Add task |
| 3 | View users |
| 4 | View all tasks |
| 5 | View tasks by user |
| 6 | View tasks by category |
| 7 | Mark task as completed |
| 8 | Delete task |
| 9 | Reassign task |
| 10 | Delete user |
| 11 | Run concurrency demo |
| 12 | Exit |

Create a user before assigning a task. Use the numeric user and task IDs displayed in the tables. IDs remain stable and are not renumbered after deletion. New tasks begin with `Pending` status.

## JSON persistence

- JavaScript saves to `javascript/data.json`.
- Java saves to `java/data.json`.
- Each version maintains its own data; the files are not automatically synchronized.
- Successful changes are saved immediately. Restarting restores users, tasks, assignments, statuses, and ID counters.
- A missing data file starts an empty application.
- Deleting a user requires confirmation and also removes that user's assigned tasks.

Use one running instance per data file. The applications do not coordinate writes from multiple terminal processes sharing the same file.

## Language-specific implementation

| Area | JavaScript | Java |
| --- | --- | --- |
| Data model | Classes with dynamically typed properties | Classes with declared field types and encapsulation |
| Collections | Arrays and callbacks such as `find`, `filter`, and `some` | `ArrayList`, streams, and lambdas |
| Organization | CommonJS modules using `require` and `module.exports` | Separate classes, imports, and access modifiers |
| Concurrency demo | `async/await`, promises, timers, and `Promise.all` | `ExecutorService`, worker threads, `CountDownLatch`, and synchronized task operations |
| JSON conversion | Built-in `JSON.parse` and `JSON.stringify` | Gson library |
| Execution | Run with Node.js | Compile with `javac`, then run on the JVM |

Both runtimes use garbage collection. Both implementations also validate user input and application rules.

## Concurrency demonstration

Create at least two users, then select option **11**. Two simulated user operations start and wait for different delays before adding demonstration tasks.

JavaScript overlaps asynchronous waiting through the event loop. `Promise.all` waits for both operations to finish; this demo does not run JavaScript CPU work in parallel. Java uses two worker threads and synchronized task creation to coordinate shared updates.

Both demos operate on a separate copy of the data. Their tasks are neither added to the main task list nor saved to JSON. This is an in-process concurrency demonstration, rather than a networked multi-user application.

## Testing

### Java automated checks

After compiling, run on macOS/Linux:

```bash
java -cp "java/out:java/lib/*" ApplicationTest
```

On Windows:

```powershell
java -cp "java/out;java/lib/*" ApplicationTest
```

The test program includes 19 checks covering user/task operations, validation, duplicates, persistence, counters, and the isolated concurrency demo. It uses temporary data rather than the application's saved data file.

### Manual checks for both versions

1. Create two users and assign a task to each.
2. View all records and filter tasks by user and category.
3. Attempt a duplicate username and duplicate task title for the same user; verify rejection.
4. Complete a task and verify its changed status.
5. Reassign a task and verify its assigned user ID.
6. Create and delete a disposable task.
7. Create a disposable user with a task; test cancelled and confirmed user deletion.
8. Run option 11 and verify that the main task list stays unchanged.
9. Exit and restart; verify that saved records and statuses are restored.

## Troubleshooting

- **Node cannot find `app.js`:** Run from the repository root using `node javascript/app.js`.
- **Java cannot find `Main`:** Compile first and use the complete runtime classpath shown above.
- **Gson classes cannot be found:** Confirm that the bundled jar is present in `java/lib/` and included in both classpaths.
- **A user or task is not found:** Check the current table and use the record's ID, not its row index.
- **A duplicate is rejected:** Use a different username or a different task title for that assigned user.
